# 主界面

本文说明主界面，解码与流程不在范围内。

## 职责

提供图片入口。界面本身不保存解码结果，选到图片后把 URI 交给 `AppViewModel` 就结束。

## 布局

内容垂直居中，从上到下依次是图标加标题、四个按钮。按钮之间留 12dp，标题与按钮之间留 48dp。左右各留 32dp。

按钮占满可用宽度，高 56dp，圆角 12dp。按钮内左边是图标，右边是文字，中间留 12dp。

## 入口

| 按钮 | 行为 | 状态 |
|---|---|---|
| 从相册 | 打开系统图片选择器，限定图片类型 | 可用 |
| 从文件 | 打开系统文件选择器，限定 `image/*` | 可用 |
| 从相机 | 申请相机权限后启动系统相机 | 可用 |
| 从历史 | 无行为 | 禁用 |

「从历史」按钮用描边样式，与其它三个填充样式的按钮区分。

## 相机流程

1. 在应用私有目录的 `camera` 子目录下建临时文件，并先清掉该目录里的旧文件。
2. 用 FileProvider 把文件转成 URI，路径配置见 `res/xml/file_paths.xml`。
3. 有相机权限就直接启动相机，没有则先申请权限。
4. 用户拍照返回后把 URI 交给 `AppViewModel`；用户取消则不做事。

## 拉起系统界面失败

系统可能没有相机应用，也可能没有文件选择器。相册选择器、文件选择器、相机权限申请、相机拍照这四个动作都按同一方式处理：捕获异常，记录日志，弹一条提示，应用继续运行。

提示文字取 `res/values/strings.xml` 里的 `toast_launch_failed`。异常自带描述不为空时，提示带上该描述。

## 边界情况

| 情况 | 行为 |
|---|---|
| 用户在选择器里取消 | `AppViewModel` 收到 null，不切换页面 |
| 用户选择的不是图片 | 文件选择器的类型过滤会拦住 |
| 相机权限被拒绝 | 弹出提示，留在主界面 |
| 拍照被取消 | 不做事，留在主界面 |
| 设备没有相机或选择器 | 弹出提示，应用不崩溃 |
