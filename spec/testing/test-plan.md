# 测试策略

本文说明自动化验证的分工与边界，手工清单见 `manual-checklist.md`。

## 三类验证

| 类型 | 位置 | 运行 | 负责内容 |
|---|---|---|---|
| 单元测试 | `app/src/test/` | `./gradlew test` | 不依赖 Android 运行时的纯逻辑 |
| 设备测试 | `app/src/androidTest/` | `./gradlew connectedAndroidTest` | 需要真实 Android 实现的部分 |
| 手工验证 | 见 `manual-checklist.md` | 真机 | 系统交互、识别效果、混淆与打包产物 |

判断一个用例该放哪里：需要断言 Android 框架类返回值的，放设备测试；能用替身实现代替真引擎的，放单元测试。

## 单元测试

### 数据模型

`AppUiState`、`Sheet.Result`、`DecodeUiState`、`DecodedBarcode`、`DecodeResult` 的默认值、复制、相等性与分支完整性。

### 引擎内部逻辑

`MlKitScanner` 的字节转十六进制、格式名映射、排序优先级与排序结果。排序覆盖四个优先级混排、同优先级保持原序、空输入、单条结果、字段保留。

### 合并逻辑

`CombinedScanner` 的合并结果覆盖：两引擎都成功时的去重与顺序、一侧为空、两侧为空、单侧失败用另一侧、单侧失败且另一侧成功为空、两侧失败时原因拼接、内容重复时保留 ML Kit 的位置点、没有位置点的结果被保留。

### AppViewModel 状态

初始状态；传入 null 不改变状态；传入有效 URI 后进入结果页并触发扫描；扫描未返回时保持解码中，由可挂起的替代实现控制；成功、空结果、多结果三种完成状态；解码失败写入错误；解码抛异常不崩溃；连续选图时后一次覆盖前一次；重复返回主界面不报错。

## 设备测试

### 结果页工具函数

`isUrl` 的前缀判断，覆盖 http、https、带路径与端口、只有协议头、无协议头的域名、纯文本、空串、缺少冒号、其它协议、大写协议头。

调色板的六组颜色、描边色值、循环取用、填充半透明与边框不透明。

多边形点击判断，覆盖各形状的内部、上下左右外部、顶点、边中点、边的延长线、空列表、单点、两点。

这些用例依赖真实的 `PointF` 坐标与 `Color` 取值，放在单元测试里只能得到默认值。

### 引擎端到端

用样图验证：二维码文本与位置点、一维码由 ML Kit 识别、无码图片返回空结果、多码图片返回多个结果。另有不依赖样图的用例：已回收的 Bitmap 返回失败、不存在的文件 URI 返回失败、纯白图片返回空结果、合并去重保留 ML Kit 的位置点。

样图放在 `app/src/androidTest/assets/qr/`，由 `tools/generate_test_images.py` 生成。缺图时相关用例记为跳过，不算失败。

### 主界面

标题与四个入口可见，相机入口可用，历史入口禁用。三个入口点击后都会拉起系统界面，那部分不在这里测。

## 不做的部分

不做 Compose 界面的单元测试，因为它们依赖 Compose 运行时。不做跨应用的界面自动化，因为要覆盖的是系统选择器与相机，成本高于手工验证。
